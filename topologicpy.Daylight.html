topologicpy.Daylight module

Direct daylight and preliminary Waldram assessment

Daylight provides direct sky calculations using TopologicPy geometry and its existing BVH visibility engine. It does not determine legal rights, infringement, compensation, planning compliance or total daylight factor.

All distances use model units; the examples assume metres. Factors and thresholds use percent: threshold=0.2 means 0.2%, not 20%. A percentage-point change is distinct from a relative percentage change.

Window host matching

Daylight.ApertureHosts(window, topologies) returns all fully containing host walls as topologyIndex / faceIndex records. An empty list means no host, and multiple records retain ambiguity for the caller to resolve. Geometric coplanarity uses native normals and plane-distance checks in both directions, independent of normal orientation or fitted eigenvector sign. Native intersection-area validation retains wall holes and concave boundaries. PrepareRoom uses the same predicate for validating its windows. The app uses this API for matching instead of duplicating the geometry calculation.

Explicit window handoff

PrepareRoom(cell, apertures=windows) accepts an authoritative list or tuple of native window Faces. Use this after Topology.AddApertures when a native wrapper cannot recover contents attached to transient wall objects. Every window still undergoes the same unique coplanar-host containment check and area-checked opening cut. No alternate geometry solver or unvalidated opening is introduced. apertures=None retains attached-aperture discovery; apertures=[] deliberately prepares an opaque room.

Quick start

from topologicpy.Daylight import Daylight
from topologicpy.Cell import Cell
from topologicpy.Face import Face
from topologicpy.Topology import Topology
from topologicpy.Vertex import Vertex

cell = Cell.Prism(Vertex.ByCoordinates(0, 0, 0), width=4, length=4,
                  height=3, placement="lowerleft")
window = Face.ByVertices([
    Vertex.ByCoordinates(1, 0, 1), Vertex.ByCoordinates(3, 0, 1),
    Vertex.ByCoordinates(3, 0, 2.5), Vertex.ByCoordinates(1, 0, 2.5)
])
cell = Topology.AddApertures(cell, [window], subTopologyType="face")
room = Daylight.PrepareRoom(cell)
plane = Daylight.WorkingPlane(cell, height=0.85)
grid = Daylight.SensorGrid(plane, spacing=0.3)

# Retained surrounding geometry appears in both scenes. Do NOT include
# an additional uncut copy of the selected room Cell.
before_scene = Daylight.PrepareScene([])
obstruction = Face.ByVertices([
    Vertex.ByCoordinates(-5, -1, 0), Vertex.ByCoordinates(9, -1, 0),
    Vertex.ByCoordinates(9, -1, 9), Vertex.ByCoordinates(-5, -1, 9)
])
after_scene = Daylight.PrepareScene([obstruction])
before = Daylight.Waldram(room, before_scene, grid=grid)
after = Daylight.Waldram(room, after_scene, grid=grid)
comparison = Daylight.Compare(before, after)
regions = Daylight.Contours(before, levels=[0.2])
diagram = Daylight.WaldramDiagram(before, sensorIndex=0)
data = Daylight.ResultData(before, includeGeometry=True)

Scene roles belong to the calling application: Before uses retained geometry plus removals; After uses retained geometry plus proposals. Prepared rooms provide real window openings; raw topologies are opaque. Display opacity and visibility do not affect calculations. All analytical surfaces are two-sided.

Method

SkyComponent uses equal-solid-angle hemisphere midpoint quadrature and projected incidence weights. It supports uniform and CIE standard overcast relative luminance. The reference is unobstructed external horizontal illuminance under the same sky. SkyFactor specialises this for horizontal sensors and a uniform sky. These methods are useful outdoors or where apertures are large; coarse angular patches may miss a narrow window altogether.

Waldram instead integrates over the room’s actual apertures. For a window triangle with area A, sensor-to-triangle distance r, aperture incidence cosine c_w and upward sensor incidence cosine c_h, its midpoint contribution is:

skyFactorPercent = 100 * A * abs(c_w) * max(c_h, 0) / (pi * r**2)

Native tessellation retains aperture holes. Uniform subdivision refines its triangles; full-scene ray queries reject occluded contributions. Overlapping coplanar windows are unioned, and nearer aperture intersections prevent projected windows being counted more than once. Windows may be vertical, inclined or horizontal. All room/context Faces must currently be planar with straight polygon boundaries. Unsupported geometry raises an error.

Windows are read from TopologicPy aperture attachments on the Cell or its Faces. Preparation checks coplanarity and complete host containment before subtracting windows from opaque analytical walls. It does not interpret aperture metadata alone as a geometric hole.

The uniform-sky method excludes reflected light, glazing/frame losses, material transmission and direct sunlight. It is a geometric sky-factor assessment, not an indoor illuminance or annual daylight simulation. SkyComponent with an overcast distribution remains a direct sky component, not total daylight factor. Full reflected-light and annual metrics are outside this version.

Sampling and sensitivity

Working-plane height defaults to 0.85 above the room’s lowest vertex elevation. Use referenceElevation explicitly for stepped or sloping floors. The plane must cut the room interior. Multiple disconnected section Faces are supported.

Grid cells are clipped to the domain; each receives an interior sensor and its actual area. Threshold area is a piecewise-constant sampled-cell estimate. It is not a continuous exact contour-area integral. Nonconvex domains and holes are retained. Grid partition area conservation is checked.

resolution accepts low, medium, high and very_high. Aperture triangles have respectively 2, 3, 4 or 5 subdivision levels, each replacing one triangle by four. The default convergence check evaluates one additional level, returns the finer values and reports their difference from the requested level. It does not certify convergence or an error bound. An explicit triangle-count limit prevents unbounded angular subdivision.

To examine spatial sensitivity, repeat Waldram with a finer grid over the same working plane, then call Convergence(coarse, fine). Large rooms and small openings may need both finer spatial and angular sampling. Tiny losses or threshold crossings should not be interpreted without this check.

Compare requires the same room, grid, method, resolution and refinement settings. It reports area gained/lost, before/after threshold percentages, percentage-point change and crossing of a configurable reference (default 50%). There is deliberately no legal pass/fail or automated risk classification.

Contours and diagrams

Contours unions above/below-threshold grid cells into native Faces. Its boundary Wires include the domain perimeter and holes. These are staircase sampled-region boundaries, not smooth interpolated isolines. The reported areas agree with the numerical threshold estimate.

WaldramDiagram maps aperture triangles to an XY sheet with azimuth in radians and y = sin(altitude)^2 / 2. The projection’s Jacobian corresponds to horizontal projected solid angle. Each patch carries its midpoint visibility and its original numerical contribution. Sheet triangles approximate curved projected edges; their geometric areas are not used to recompute sky factors. Horizon-straddling or degenerate projected patches can be omitted and are counted. Azimuth seam patches may extend beyond the nominal sheet width. Numeric sky factor remains the complete calculation even if a sheet patch is omitted. This is an explanatory sampled diagram, not an exact silhouette.

Calibrated diagrams

For scientific charts, use WaldramDiagram(result, index, calibrated=True) or WaldramDiagramComparison(before, after, index). The existing native Face sheet remains available as the default for compatibility. The calibrated data are JSON-compatible and contain no SVG or other presentation code.

The uniform-sky, horizontal-plane chart has x = azimuth in degrees and y = sin(altitude)^2, on a common 0..1 vertical range. Equal chart areas represent equal sky-factor contributions. An unobstructed 180-degree frame contributes 50%, while a full 360-degree frame contributes 100%. These are not the vertical sky-component or CIE-overcast chart conventions. Altitude tick positions are nonlinear. The frame is centred on the first aperture’s horizontal normal, or on the supplied horizontal direction; the returned bearing is clockwise from model +Y. Automatic frames use -90..90 degrees for forward-facing windows and -180..180 where required. Explicit frames deliberately crop to their range.

graticule provides azimuth/altitude lines and, for a forward 180-degree frame, the droop curves of horizontal edges parallel to the window plane. Their central elevations are spaced by gridStep (default 15 degrees). apertureOutlines adaptively projects straight native boundary edges, including internal boundaries, clipping at the horizon and angular seam. projectionTolerance is the maximum midpoint deviation in normalized chart coordinates (azimuth divided by 360 and projected height), not an error bound for visibility or sky factor. Edges are approximated to depth 14.

Visibility uses independent angular cells (default maximum width/height 0.5 degrees), sampled at projected-area midpoints. Each rectangle’s exact projected area determines its sky-factor weight. Cells outside apertures are excluded; holes remain excluded. Region categories distinguish visible sky and the nearest opaque scene source. Pass one string per topology using PrepareScene(..., labels=...) to preserve semantic obstruction labels. The default label is Existing; selected-room occlusion is labelled Room. Source labels do not change the geometry identity or the physical calculation. The plan record contains native floor footprints, window vertices and world-XY axes for an optional context inset; it is not a boundary survey.

Comparison uses identical axes, angular grids and aperture masks. It returns retained, lost, gained and blocked regions, with loss/gain as percentages of unobstructed external horizontal illuminance. diagramChangePP is gained minus lost. assessmentChangePP comes from the original quadrature. reconciliation reports both integrations and their signed difference in percentage points. The comparison refines the chart grid once by default if that difference exceeds reconciliationTolerance (default 0.05 pp), up to the 600,000-cell limit. A discrepancy remains explicit; no value is forced to match. Refine the original assessment too when needed. maxRefinements can be 0..3, subject to that limit. Cancellation callbacks are supported.

Recalculate assessments to populate the new geometry cache. These sampled obstruction silhouettes and adaptive aperture curves are preliminary numerical outputs, not certified survey drawings or legal determinations.

Records and persistence

Geometry identities use canonical planar polygon boundaries rather than BREP serialization text, which can change when native preparation updates internal representation data. Ring start/winding and Face/hole ordering are ignored; coordinates are rounded to nine decimal places in model units. Grid identities retain sensor/cell ordering. Aperture holes and window geometry remain part of the identity, so genuinely different assessments are still rejected.

Prepared rooms, grids and scenes are snapshots, immutable by convention. Rebuild after edits; do not change record arrays or geometry in place. Results retain method version, identities, coordinates, areas, settings, assumptions, warnings, refinement metadata and summary values. The private _diagram cache holds live ray geometry.

ResultData produces JSON-compatible data without native geometry/cache. includeGeometry=True adds working-plane and clipped-cell BREP strings. Recalculate from source geometry to restore a diagram cache. The result export is not a complete project or prepared-scene persistence format.

Failures use ValueError rather than silent alternative calculations. Cancellation callbacks raise InterruptedError during angular integration and ray tracing. Native geometry preparation is synchronous and not interruptible.

API reference

Direct daylight geometry and preliminary Waldram studies.

Factors are percentages of unobstructed external horizontal illuminance. Lengths use model units. No reflections, glazing losses or legal classification.

static PrepareRoom(cell, *, apertures=None, tolerance=0.0001)

Validate Cell/windows and cut actual analytical openings.

Reads Faces attached by Topology.AddApertures to Cell or its Faces. An explicit apertures list is authoritative when supplied; this avoids relying on subtopology content identity across native wrapper builds. With apertures=None, attached apertures are discovered as before. Windows must be contained in one coplanar host. Overlaps are unioned. Only planar straight-edged geometry supported. Does not mutate input.

static Waldram(room, scene, *, grid=None, height=0.85, spacing=0.3, threshold=0.2, resolution='medium', checkConvergence=True, cancelled=None)

Aperture-focused uniform-sky horizontal assessment (%).

Includes room opaque faces automatically. Do not also supply its uncut Cell. Midpoint quadrature subdivides each aperture triangle. Optional convergence checks one finer angular level and RETURNS the finer result. Spatial refinement is separate. Threshold 0.2 means 0.2 percent. No glazing/frame losses, reflections, sunlight or legal conclusions.

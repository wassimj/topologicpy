static AccessGraph(model, viaConnectingElements: bool = False, semanticConnections: bool = True, spatialConnections: bool = False, dictionaryMode: str = 'Full', scale: float = 1.0, circleSides: int = 24, tolerance: float = 0.0001, silent: bool = False)

Creates an access TGraph from an already parsed IFCModel.

Only IfcSpace entities become principal graph vertices.

The connecting elements are:

  • unfilled IfcOpeningElement entities;

  • IfcOpeningElement entities filled by IfcDoor or IfcDoorStandardCase;

  • IfcStairFlight entities;

  • IfcStair entities that are not decomposed into IfcStairFlight entities;

  • IfcRampFlight entities;

  • IfcRamp entities that are not decomposed into IfcRampFlight entities; and

  • IfcTransportElement entities identified as elevators or lifts.

Door geometry is never imported. Door access uses the geometry of its IfcOpeningElement. Vertical-circulation elements use their own geometry.

When semanticConnections is True, IfcRelSpaceBoundary relationships are used first. For decomposed stairs and ramps, boundaries associated with the parent assembly are also considered.

When spatialConnections is True, connecting elements with fewer than two semantic space connections are tested geometrically against the IfcSpace cells using only the “overlaps” and “touches” spatial relationships. Completely isolated spaces are then tested directly against the other spaces using the same relationships.

If set to True, connecting elements become intermediate graph vertices. Otherwise, they become direct graph edges between adjacent spaces. Default is False.

If set to True, connections are first derived from IFC semantic relationships. Default is True.

spatialConnectionsbool , optional

If set to True, unresolved connecting elements and isolated spaces are tested using spatial relationships. Default is False.

The scale factor applied to imported coordinates. Default is 1.0.

static AdjacencyGraph(model, nodeTypes: list = None, connectingElementTypes: list = None, viaConnectingElements: bool = False, semanticConnections: bool = True, spatialConnections: bool = False, spatialRelationshipTypes: list = None, proximityValues: list = None, proximityLabels: list = None, useShortestDistance: bool = False, dictionaryMode: str = 'Full', scale: float = 1.0, circleSides: int = 24, mantissa: int = 6, tolerance: float = 0.0001, silent: bool = False)

Creates a general-purpose IFC adjacency TGraph from semantic and spatial relationships.

The entities specified by nodeTypes form the principal graph vertices. The entities specified by connectingElementTypes mediate semantic adjacency and are also included in the spatial relationship graph when spatialConnections is True.

Semantic adjacency is derived from IFC relationship entities, including space boundaries, element connections, and distribution-port connections. Spatial adjacency is delegated entirely to TGraph.BySpatialRelationships and merged with the semantic graph by the persistent IFC_id stored on each topology.

connectingElementTypeslist , optional

IFC types that constitute connecting elements. Default is [“IfcWall”, “IfcSlab”].

viaConnectingElementsbool , optional

If True, semantic connections pass through connecting-element vertices. If False, each semantic connecting element creates direct edges among its semantically associated nodes. When spatialConnections is True, selected connecting elements are still retained as graph vertices because they participate directly in the spatial relationship graph. Default is False.

If True, IFC relationship entities are used to derive semantic adjacency. Default is True.

scalefloat , optional

The scale factor applied to imported IFC coordinates. Default is 1.0.

circleSidesint , optional

The number of sides used to approximate circular geometry. Default is 24.

mantissaint , optional

Coordinate and spatial-result rounding precision. Default is 6.

tolerancefloat , optional

The desired geometric tolerance. Default is 0.0001.

static AnalyticalFaces(model, circleSides: int = 24, scale: float = 1.0, angTolerance: float = 5.0, tolerance: float = 0.0001, silent: bool = False) → list

Returns analytical faces for IFC walls, slabs, and roofs.

Exterior constructions are represented by their outer major face. Interior constructions are represented by a medial face halfway between their two major parallel faces.

Classification first uses physical IfcRelSpaceBoundary relationships. If these are absent, common IsExternal property values and limited IFC type/name fallbacks are used. Ambiguous elements are skipped.

scalefloat , optional

Scale factor applied to imported IFC geometry. Default is 1.0.

angTolerancefloat , optional

Maximum angular deviation, in degrees, when pairing the two major parallel faces. Default is 5.0.

tolerancefloat , optional

The desired geometric tolerance. Default is 0.0001.

silentbool , optional

If True, errors, warnings, and summary information are suppressed. Default is False.

Returns
list

A list of topologic_core.Face objects, or None if no analytical faces can be generated.

Notes

This proof of concept assumes each construction is predominantly a thin extrusion with two dominant approximately parallel faces.

static DoorSpaceCardinalityReport(file, connectorTypes: list = None, includeOpenings: bool = True, includeWindows: bool = False, includeZeroSpaceConnectors: bool = True, highCardinalityThreshold: int = 2, silent: bool = False)

Returns a diagnostic report of door/opening-to-space cardinalities in an IFC file.

The method inspects IfcRelSpaceBoundary relationships to determine how many IfcSpace entities are associated with each connector element. It also uses IfcRelFillsElement to resolve IfcOpeningElement entities to their filling elements, usually IfcDoor or IfcWindow.

A correctly exported door connecting two rooms is normally expected to have a space_count of 2. Doors with one related space may indicate an external door, incomplete space boundaries, or an export issue. Doors with more than two related spaces are usually suspicious and are flagged as high_cardinality.

Parameters

IFC connector types to include. If None, defaults to IfcDoor and, optionally, IfcOpeningElement and IfcWindow depending on the other parameters. Default is None.

includeOpeningsbool , optional

If set to True, unresolved IfcOpeningElement entities are included in the report. Default is True.

includeWindowsbool , optional

If set to True, IfcWindow and IfcWindowStandardCase are included. Default is False.

includeZeroSpaceConnectorsbool , optional

If set to True, connector elements found through IfcRelFillsElement are included even if no related IfcSpace was found. Default is True.

highCardinalityThresholdint , optional

Cardinalities above this number are labelled high_cardinality. Default is 2.

silentbool , optional

If set to True, error and warning messages are suppressed. Default is False.

static Export(model, path: str, overwrite: bool = False, preserveSourceFormatting: bool = True, validate: bool = True, updateModel: bool = True, silent: bool = False) → str

Exports an in-memory IFCModel to an IFC STEP Physical File.

The method is intended for round-trip export of models created with IFC.ModelByPath and subsequently modified in memory. Unchanged STEP entity statements are preserved verbatim from the source file whenever possible. New or modified IFCFastEntity objects are serialized from their in-memory values.

Parameters
modelIFCModel

The input in-memory IFC model.

pathstr

The output IFC file path. The .ifc extension is added when the input path has no extension.

overwritebool , optional

If set to True, an existing output file may be replaced atomically. Default is False.

preserveSourceFormattingbool , optional

If set to True and the model has a readable sourcePath, unchanged source entity statements are copied verbatim. This is the preferred round-trip mode because the current lightweight parser represents both quoted STEP strings and enumeration values as Python strings. Default is True.

validatebool , optional

If set to True, validates entity ids and references before writing, reparses the temporary exported file, and verifies that its parsed entities match the in-memory model before replacing the destination. Default is True.

updateModelbool , optional

If set to True after a successful export, updates model.sourcePath and its preserved header and marks the model as clean. The model revision is not changed because export does not alter its entities. Default is True.

silentbool , optional

If set to True, suppresses errors, warnings, and information messages. Default is False.

Returns
str

The absolute exported IFC path, or None if the operation fails.

Notes

The exporter writes the existing parsed IFC model; it does not rebuild product geometry. It therefore preserves semantic relationships added by IFC.SemanticRelationshipsByGraph together with the original IFC entities and references.

For source-backed models, unchanged entity statements are preserved exactly. For a model created only from a raw entity dictionary, generic serialization is used. The four relationship classes currently created by IFC.SemanticRelationshipsByGraph are serialized explicitly and do not depend on string/enumeration heuristics.

static SemanticRelationshipsByGraph(model, graph, annotateGraph: bool = True, silent: bool = False) → dict

Creates missing in-memory IFC semantic relationship entities from an IFC adjacency TGraph.

The input graph and IFCModel must refer to the same in-memory model. Each participating graph vertex must contain an IFC_id referring to an entity in that model. Existing IFC relationships are detected and are not duplicated.

The method uses the following conservative mapping:

  • IfcSpace to non-space element -> IfcRelSpaceBoundary

  • IfcDistributionPort to IfcDistributionPort -> IfcRelConnectsPorts

  • IfcDistributionPort to element -> IfcRelConnectsPortToElement

  • element to element -> IfcRelConnectsElements

Direct space-to-space relationships are not guessed. When a collapsed graph edge contains connecting_element_id, connector_id, or opening_id, the method instead creates a space-to-connecting-element relationship for each endpoint.

This method modifies only the returned in-memory entity dictionary. It does not write an IFC STEP file. IFC export support can subsequently serialise the returned entities dictionary.

Parameters
modelIFCModel

The mutable in-memory IFC model that owns the graph entities.

graphtopologicpy.TGraph

The input IFC adjacency TGraph. Its vertex dictionaries must contain valid IFC_id values.

annotateGraphbool , optional

If set to True, graph-edge dictionaries are annotated with the IFC relationship ids, GlobalIds, and classes that were created or matched. The graph dictionary is also updated with a summary. Default is True.

silentbool , optional

If set to True, error and warning messages are suppressed. Default is False.

Returns
dict

A dictionary containing:

  • graph: the optionally annotated input graph;

  • entities: the parsed IFC entities plus inferred relationships;

  • relationshipEntities: newly created IFCFastEntity objects;

  • addedRelationships: readable records for created relationships;

  • existingRelationships: graph candidates already represented in IFC;

static ThermalCellComplex(model, separatorTypes: list = None, margin: float = 0.5, circleSides: int = 24, scale: float = 1.0, tolerance: float = 0.0001, silent: bool = False)

Creates a proof-of-concept thermal CellComplex from an IFCModel.

Construction elements are reduced to oversized zero-thickness analytical planes. The planes sequentially slice one enclosing cell. IfcSpace geometry is used only to provide interior seed vertices that select and label the resulting construction-derived cells.

This proof of concept is intended for predominantly planar walls, slabs, roofs, curtain walls, and virtual elements. Each construction element is represented by a plane through its centroid, parallel to its largest face. The plane is enlarged sufficiently to cross the complete model enclosure.

Parameters
modelIFCModel

The input in-memory IFC model.

separatorTypeslist , optional

IFC types used as construction separators. Default is [“IfcWall”, “IfcSlab”, “IfcRoof”, “IfcCurtainWall”, “IfcVirtualElement”].

marginfloat , optional

Padding added to the enclosing cell in model units. Default is 0.5.

circleSidesint , optional

Number of sides used for circular IFC geometry. Default is 24.

scalefloat , optional

Scale factor applied to imported IFC geometry. Default is 1.0.

tolerancefloat , optional

The desired geometric tolerance. Default is 0.0001.

silentbool , optional

If True, suppresses errors, warnings, and progress information. Default is False.

Returns
topologic_core.CellComplex

The construction-derived thermal CellComplex, or None on failure.

Notes

This method deliberately extends each separator across the entire model. It can therefore over-partition non-convex or highly articulated buildings. Unwanted regions are discarded by selecting only cells containing an IfcSpace interior seed vertex.
